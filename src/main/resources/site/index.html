01

一个后台，管好发布的每一步

从上传到灰度、从监控到回滚，每一步都有清楚的数据和随手可用的开关。

  1. 先推给一部分设备，安装和启动没问题再一步步放到全部；也可以约好时间自动调。

  2. 发布时自动为最近几个版本生成 bsdiff 补丁，设备只下载有变化的部分。

  3. 回到上一版本、任意更早的版本，或者安装包内置的版本。

  4. 每个版本推送、装上、启动失败多少一目了然；失败偏多时告警，钉钉、飞书、企业微信都能收。

  5. 批量生成或导入口令，设上限和有效期；兑换接口 HMAC 签名、防重放。

  6. 口令归属代理，代理有自己的后台；按今天、本周、累计看谁在带量。

02

三步接入，当天上线

不用学新的 SDK，也不用改业务代码，用的就是 expo-updates 本来的协议。

  1. 01

    改 app.json

    填上更新地址和签名证书，重新打一次包。

    "updates": {
  "url": "https://ota.example.com/m/my-app",
  "requestHeaders": {
    "expo-channel-name": "production"
  },
  "codeSigningCertificate": "./certs/certificate.pem"
}
  2. 02

    一条命令发布

    导出、只传有变化的文件、发布到指定渠道，适合放进 CI。

    $ ota publish --app my-app --rollout 20
✓ 导出完成 · 37 个文件，只上传 2 个
✓ 生成增量补丁 · 3 个版本
✓ 已发布到 production · 灰度 20%
  3. 03

    设备自动更新

    App 启动时检查更新，后台下载、下次打开生效；全程签名校验。

03

安全，是默认设置

签名的更新、严格的会话和完整的操作记录，不用额外配置。

代码签名

每个 App 独立的签名密钥，设备只装验过签名的更新。

两步验证

身份验证器动态码加一次性恢复码，可以要求所有管理员开启。

细分权限

成员按 App、按操作授权；停用和改密码后，已登录的会话立即失效。

全量日志

每一次发布、切换、口令变更都有记录，可搜索、可导出。

加密备份

密钥和配置加密备份，一键恢复到新服务器。

数据自持

数据库、文件、密钥都在你自己的服务器上。
